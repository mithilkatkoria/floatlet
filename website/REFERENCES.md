# Implementation references and assets

The source of truth for capabilities and release details is the [Floatlet repository](https://github.com/mithilkatkoria/floatlet) and its published v0.4.0 release. Planned features are not presented as released features.

Implementation references:

- [Astro documentation](https://docs.astro.build/en/getting-started/): static pages, client scripts and framework configuration.
- [Vercel Astro integration](https://vercel.com/docs/frameworks/frontend/astro): static hosting and deployments.
- [Lighthouse](https://developer.chrome.com/docs/lighthouse/overview): laboratory diagnostics, not real-user performance evidence.
- [Google consent mode](https://developers.google.com/tag-platform/security/concepts/consent-mode) and [Clarity consent API](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-consent-api-v2): inactive measurement scaffolding. Actual vendor traffic has not been enabled or validated.
- [Animation from interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html): reduced-motion behavior.

All visible illustration is original HTML/CSS/SVG: the Floatlet mark, capsule, desktop sample and F01 artwork. Sample track titles are fictional and no music plays. No user screenshots, album artwork, caller photos, private calendar data, paid fonts or third-party media are deployed. Fonts come from the visitor's system. Site source inherits the repository's MIT license. Framework dependency licenses are retained through the package lock and installed package metadata.
